## [Unreleased]

### Added
- Initial repository scaffold: README, MIT license, Python `.gitignore`, and this changelog.
- Plan 1 architecture research: `docs/research/stage-2-newsroom-architecture.md`. Answers the eight agentic-workflow and agentic-loop design questions, pins the platform publish seam against the live `censurado-web` code, chooses plain Python with pydantic-ai only at the finalize seam, maps reuse of gamentic / websearch-skill / hermes, and lays out a ten-step, independently-testable Plan 2 build.
- Step 0 (the brain build begins): the `newsroom` package skeleton (isolated `brain`, `personas`, `inference`, `research`, `publish`, `contracts` sub-packages) and the versioned `prompts/` tree; the one shared in-repo test fake (`testkit`) serving a scriptable OpenAI-dialect `/v1/chat/completions` that rejects any output-length cap and a faithful `/articles` publish stand-in (both scopes including the 403 path, content-hash idempotency, author binding, strict unknown-field rejection); the vendored `article.schema.json` (byte-identical to the platform) with a CI drift guard; the harness section enum; a content-hash port proven byte-equal to the platform's Go implementation via an independent Go reference vector; and a green pytest suite driven over real HTTP. Toolchain is uv (pyproject, Makefile, .env.example).
- Step 1 (inference adapter): `newsroom/inference`, an OpenAI Chat-Completions dialect adapter (`chat`: `ChatRequest` to `ChatResponse`) adapted from gamentic with every output-length cap stripped (no `max_tokens`, ever). Per-backend capability gating (`supports_thinking`, `supports_grammar`, and the stop-list budget); role-based provider resolution (`NEWSROOM_ROLE_<ROLE>_*` to `NEWSROOM_INFERENCE_*` to dialect default) so the evaluator can target a different endpoint than the drafter (`endpoints_distinct`); and a one-retry-on-connection-drop transport (timeouts and status errors are not retried). The shared test fake gained scriptable tool calls and usage. 22 new tests (86 total, ruff clean).
- Step 2 (persona store): the brain-owned SQLite database (`newsroom/db.py`, the full B.5 schema for `personas` / `runs` / `assignments` with the beat and mode CHECK constraints, foreign keys, and the unique idempotency index) and a typed persona store (`newsroom/personas`, `Persona` + `PersonaStore` CRUD). A persona's `id` becomes the publish-seam author and is derived from `display_name` when blank; `beat` reuses the harness section enum so it cannot drift from the publish vocabulary; the positive and NEGATIVE few-shot exemplars and preferred sources round-trip as JSON arrays; `updated_at` advances on edit via an injectable clock. In-process only (nothing under `newsroom/` opens a network to reach it). `delete` wraps the foreign-key violation from a still-referenced persona as a `ValueError`, keeping the store's error contract consistent. 25 new tests (113 total, ruff clean), covering the full round-trip including negative few-shots, the validation and not-found paths, file persistence across connections, the referenced-delete guard, and the raw CHECK / foreign-key / unique-index guarantees.
- Step 3 (async persona synthesis): the brain's first HTTP surface (`newsroom/brain`, FastAPI). `POST /personas` validates the beat against the harness section enum and returns `202 Accepted` immediately with a job id and a `Location` to poll; the single uncapped model call runs off the request in a worker thread (`newsroom/brain/synthesis.py`), then the synthesized persona is persisted through the Step 2 store. Clients poll `GET /personas/jobs/{job_id}` to `done` or `failed`, then read the draft at `GET /personas/{persona_id}` (plus `GET /personas` to list). The synthesis prompt (`prompts/persona/synthesize.md`) uses direct role-play framing (the model is told to BE the persona, the framing local Gemma-class models need) and asks for contrastive positive and negative few-shots, with no length limit. A bad model reply (non-JSON, a missing required field, a store conflict) becomes a `failed` job, never a crash. One `threading.Lock` serializes the single shared SQLite connection (opened `check_same_thread=False`) across the request loop and the background thread. The shared fake gained a `threading.Event` chat gate (`hold_chat` / `release_chat`, open by default) so a test can prove the route answers without waiting for the model. Prompt rendering (`newsroom/prompts.py`) substitutes `{{TOKEN}}` placeholders in a single pass, so a value cannot be re-expanded by a later key. 16 new tests (129 total, ruff clean), driven over real HTTP, including the held-model non-blocking proof, the negative-few-shot round-trip through the route, the synchronous beat rejection, the failed-job paths, and the single-pass render guarantee.
- Step 5 (per-article pipeline): the one model-driven loop in the harness, made bounded (`newsroom/pipeline`). `run_article_pipeline` drives one assignment top to bottom: OUTLINE (one call), then `for sweep in range(max_sweeps)` DRAFT (persona re-injected fresh every call, warm temperature, body unbounded) and EVALUATE, then ENRICH and FACT-CHECK (both persona-blind), then FINALIZE. The evaluator is collapsed review-and-judge returning `{verdict, feedback, failing_sections}`; it resolves to a different endpoint than the drafter (model-driven, scriptable PASS/REVISE) or DEGRADES to a rules-grounded check (CitationVerify passes and the ledger is non-empty) when only one backend is configured. The loop stops on PASS, on the no-progress detector (the IDENTICAL non-empty failing-section set two sweeps running, not whole-draft similarity), or at `max_sweeps`. Over all of it sits the shared per-article budget (`pipeline/budget.py`, token plus wall-clock), debited by every stage including the evaluator and the fact-check revise; on exhaustion the assignment is DROPPED (`budget_exhausted`), the ledger digest is kept for audit, and the complete, never-truncated body is never persisted or published (a budget is a loop bound, dropping keeps it separate from the no-output-cap rule). A finalize failure is isolated the same way (`finalize_failed`), so one bad article never crashes a run. FINALIZE is the one pydantic-ai seam (1.107.0, added this step): a prompted-JSON call validated into a `FinalizedDraft` with exactly one re-prompt on failure (`retries={'output': 1}`, no `max_tokens`); `author` (the persona id) and `section` (the assignment's) are authoritative, set in code, never model-chosen, and a reserved `metadata.newsroom` provenance namespace is stamped. The idempotency key is minted from the finalized article (`hash(assignment_id + content_hash)`, B.0), persisted on the assignment BEFORE any publish so a post-finalize crash replays the byte-identical body. Supporting: the runs/assignments store (`newsroom/runs`, the `assigned -> drafting -> ready | dropped` lifecycle), the publish payload as typed Pydantic models (`contracts/article.py`, body never length-capped, section pinned to the harness enum), and a shared JSON extractor (`newsroom/jsonio.py`) tolerant of a local model's code fences and prose-wrapped output, refactored out of the research and synthesis duplication. The six journalist prompts replace their placeholders, all cap-free. Store writes take an optional lock so concurrent pipelines never race the brain's single shared SQLite connection. 50 new tests (203 total, ruff clean): the three contract proofs (PASS on sweep 2 is exactly two drafts; never-PASS is exactly `max_sweeps` drafts; budget exhaustion mid-draft drops the assignment, makes no POST, and persists no body), plus the stall and empty-set and rules-degrade and finalize-failure and prose-wrapped-JSON paths, the finalize seam over real pydantic-ai against the fake, the budget limits, and the full assignment lifecycle.
- Step 6 (manager + fan-out): the harness's orchestrator-workers seam (`newsroom/manager`). `run_manager` is a BOUNDED ReAct loop: each turn the manager model returns one JSON action (search or assign), guarded all at once by `max_manager_steps`, a tool-call budget, a circuit breaker (a malformed action, an identical query, a search that adds no new story, or a failed search counts as a no-progress strike, and a productive step resets it, which also catches K distinct-but-useless searches the way the research stall detector does), and an optional shared budget. A cap, the breaker, or an exhausted budget forces a terminal that DEGRADES to whatever the manager has ranked (the candidates its searches surfaced) rather than failing the run, and a broken backend (a 5xx, a timeout, a dropped connection, a body missing `choices`) is caught the same way, so the loop always returns a manifest. The manager is the SOLE fan-out point and CLAMPS `len(assignments) <= n_max`. Coverage memory (`coverage.py`, a new `coverage` table written by publish at Step 7 and read here) keeps news fresh and non-repeating: a rules-first fingerprint (a normalized headline plus topic and entity tokens, compared by Jaccard similarity, persisted as JSON so multi-word entities survive the round-trip, with a whole-headline fallback so a pure-acronym headline never fingerprints to empty) classifies each candidate as DUPLICATE (drop, a hard floor the model cannot override, so the harness never republishes a near-identical story), FOLLOW_UP (attach the prior article's slug and brief the journalist to cover only what is new and cite it), or NEW; on top of that floor the manager model's own per-candidate verdict makes the final follow-up-versus-drop-versus-new call. `section` is authoritative from the persona's beat, and a FOLLOW_UP only attaches a slug that actually exists in coverage (never a hallucinated one). The deterministic fan-out (`dispatch.py`) is the one place a run turns the manifest into running journalists: it persists each assignment, then runs the Step 5 per-article pipeline for each through a small thread pool (concurrency 1 to 2), which is exactly where Step 5's deferred `run_sync`-off-the-event-loop offload lands; the shared SQLite connection is serialized under one lock, outcomes come back in manifest order (not completion order), and one article failing for any reason is isolated to that article so it never crashes the run. `preflight.py` wires Step 5's deferred `endpoints_distinct` startup check: it reports whether the evaluator resolves to a distinct endpoint from the drafter (otherwise the pipeline's rules-grounded evaluator degrade is active) and fails fast when an operator requires a distinct evaluator. 45 new tests (248 total, ruff clean): the four build-plan contracts (`len <= n_max`; a step-cap forces a partial manifest that never fails the run; no cross-persona context bleed, proven at concurrency 1 and 2; an AST guard that the journalist graph has no edge constructing another journalist or manager, hardened against aliased and indirect calls), plus the circuit-breaker, stall, malformed, tool-budget, shared-budget, and transport-failure terminals, the two-layer triage (the model can demote a rules-follow-up to new or flag a duplicate the fingerprint missed, but cannot override the duplicate floor), the multi-word-entity fingerprint round-trip, the empty-fingerprint floor, the hallucinated-slug fallback, per-article failure isolation, the lock, and the preflight both ways. Adversarially reviewed (a five-dimension multi-agent pass, 11 findings all confirmed real and folded in: the unguarded manager chat call, the fingerprint persistence dropping multi-word tokens, empty-fingerprint republication, hallucinated follow-up slugs, the ignored model triage verdict, and three test-rigor gaps).
- Step 7 (publish client): the harness's second real process boundary, raw HTTP to the platform `/articles` seam (`newsroom/publish`). The CLI-versus-HTTP question deferred from Plan 1 is resolved in favor of raw HTTP: the brain stack stays isolated (no Go binary to install or pin) and the harness already vendors the schema, the section enum, and the content hash, so it owns the local validation the CLI would otherwise provide. `publish_article` is pure transport: it validates `section` against the harness enum LOCALLY before any POST (a stray section would mint an orphan `/section/<slug>` page on the public site), sends the article under the content-derived `Idempotency-Key` persisted at finalize, and maps the response to a typed `PublishResult` (201 created, 200 replayed, 403 insufficient_scope or author_mismatch, 400/422 typed, and a transport fault degraded to a typed result rather than a raise). It enforces the seam's own invariant: if the article handed to it has drifted from the finalized content the key was minted for, it refuses with `content_hash_drift` rather than POST a body that contradicts the key, and an id-less 2xx is a `malformed_success`, not a silent ok. `publish_assignment` is the COLLECT to PUBLISH tail with side effects: on a created or replayed success it records ONE coverage row (the Step 6 memory) and marks the assignment published, in that order so the only crash window is benign (a re-run replays the idempotent 200 and re-records, rather than leaving a published assignment with a coverage row the guard could never backfill), and it records once per assignment so a replay never double-records. The operator key holds BOTH scopes; `publish-any` alone 403s, which is why a write-only key cannot author as a persona. 14 new tests (262 total, ruff clean) against the shared fake: the five build-plan contracts (a write-less key 403s; a finalized body POSTs once carrying the persisted key and a matching content hash; a replay is an idempotent 200 under the identical key with no double-publish; a stray section is rejected before any POST; `metadata.newsroom` reaches the wire and is accepted), plus author binding, the transport degrade, the content-hash-drift refusal, a faithfully-reconstructed-article replay, the id-less-2xx mapping, and the side-effecting wrapper (mark published, record coverage, skip both on failure, no double-record on replay). Adversarially reviewed (a four-dimension multi-agent pass, 7 findings all confirmed real and folded in: the content-hash/key consistency guard, the id-less-2xx mapping, the coverage-record ordering, and four test-rigor gaps).
- Step 4 (research tool + claim-source ledger): a bounded plan-then-search research loop (`newsroom/research`). The claim-source ledger (`ledger.py`) is the article's grounding spine: rows of `{claim, url, snippet, fetched_at}`, deduplicated by URL, with a stable order- and clock-independent `digest` for the audit anchor. The research tool (`tool.py`) reuses `websearch-skill` whole (added as a pinned git dependency `websearch-skill @ v0.1.0`): it builds one keyless `AgentIO` and runs time-filtered (`freshness`) searches, mapping the result envelope into `SearchResult` rows and degrading an error envelope to an empty list rather than raising; the dependency is imported lazily, only when research runs. The loop (`loop.py`) plans 3 to 6 sub-questions with one uncapped model call, then searches each deterministically under three guards: `max_research_steps` (caps the searches), a ledger-stall detector (aborts after `research_stall_limit` consecutive steps that add no new-URL row, which catches K distinct successful searches that each return junk, a case a circuit breaker misses), and an optional shared per-article budget gate. 24 new tests (153 total, ruff clean): the ledger dedup and digest, the loop's cap-halts and stall-fires proofs (with distinct queries) plus the budget gate, planning parsed from the model over real HTTP, and the tool mapping / time-filter / error-degrade driven against the real `websearch-skill` library with a faked search backend.

### Changed
- Recorded image generation as a future brain feature in the architecture doc (a new appendix): a later iteration adds a ComfyUI-template image node reusing the gamentic approach, slotted in as one more bounded, persona-blind per-article pipeline step (not a new fan-out point), attached either as a Markdown body image or via the `metadata.newsroom` namespace, so it needs no platform schema change. The platform stays media-light; the brain generates and attaches imagery on its side.
- Re-questioned Plan 1 under the precise "agentic workflow" term (not a generic workflow) and audited the research doc section by section. Verdict: the substance was already agentic-native and no design decision was skewed. Tightened A.2 (separated the halting proof, a monotonic harness bound, from the quality guards) and appended a Plan 2 refinements section (local-model persona handling, persona-blind fact-check, context-rot handling, why a small output cap can cause a runaway loop).
